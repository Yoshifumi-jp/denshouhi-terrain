## 目的（このテーマ1つ）
国土地理院から新しい取得日の伝承碑 CSV を data/raw/<取得日>/ に置いて更新コマンドを1回実行すると、
(1) 前回のデータとの「追加・変更・削除」の一覧を出して保存し、(2) 成果物（data/processed/ と output/）を作り直し、(3) 更新履歴を記録する。
※「差分だけ再計算」は、既存のキャッシュ（標高・地形分類は座標ごとに保存済み）で実現する。各処理は全碑を対象に走らせるが、
問い合わせが発生するのは新しい碑・位置が変わった碑の座標だけになる。比較地点は碑の ID ごとに乱数を固定しているので、既存の碑の比較地点は変わらない。
公開用ページの作成（GitHub Pages）は次の指示書 M6-02 で行う。この指示書では作らない。

## 対象ファイル
- 新規：src/update.py、tests/test_update.py
- 既存の src/ の各ファイルは変更しない（load_monuments.py の load_csv・validate_dataframe・filter_by_prefecture・get_fetch_date・REQUIRED_COLUMNS などは import して使ってよい）
- data/raw/ は読むだけ（書き込み・削除しない）

## コマンド
```
python src/update.py --pref 36 [--old <古いCSVのパス>] [--new <新しいCSVのパス>] [--dry-run]
```
- `--pref`：県コード 01〜47（all は不可。他のスクリプトと同じエラー文で終了）
- `--new` 省略時：data/raw/ の最も新しい日付フォルダの CSV（load_monuments.get_latest_raw_csv を使う）
- `--old` 省略時：次の順で決める
  1. 更新履歴（下記）にこの県の「完了」の行があれば、最後の「完了」行の「新データのファイル」
  2. なければ data/raw/ で2番目に新しい日付フォルダの CSV（そのフォルダに CSV が2つ以上あればエラーで止める）
  3. それもなければ「初回」とし、古いデータなし（新データの碑はすべて「追加」）
- `--old` と `--new` が同じファイルを指すときは「古いデータと新しいデータが同じファイルです」と出して終了（終了コード1）
- `--dry-run`：差分の判定・表示・差分ファイルの保存までで止める。成果物の作り直しと更新履歴の記録はしない
- データ取得日は load_monuments.get_fetch_date（親フォルダ名が YYYY-MM-DD なら その日付、違えば「不明」）で決める

## 差分の判定
- 新旧どちらも load_csv → validate_dataframe → filter_by_prefecture で対象県の碑に絞ってから比べる（他県の行は無視）
- キーは ID。新旧どちらかで ID が重複していたら、重複した ID を表示してエラーで止める（終了コード1）
- 区分：
  - 追加：新にだけある ID
  - 削除：旧にだけある ID
  - 変更：両方にあり、比較する列のどれかが違う
- 比較する列：REQUIRED_COLUMNS のうち ID 以外の11列（碑名、建立年、所在地、災害名、災害種別、伝承内容、緯度、経度、公開日、修正等公開日、制限事項）
  - 文字の列は、前後の空白を取り除き、空欄（NaN）は空文字として比べる（前後の空白だけの違いは変更としない）
  - 緯度・経度は数値にして、差の絶対値が 0.0000001 より大きいときだけ違うとする
- 「位置の変更」：緯度か経度が違えば「あり」、違わなければ「なし」（追加・削除は空欄）

## 差分ファイル（--dry-run でも保存する）
- 保存先：output/diff/diff_<県コード>_<旧取得日>_<新取得日>.csv（初回は旧取得日を「none」。例 diff_36_none_2026-09-24.csv）。output/diff/ がなければ作る
- 文字コード utf-8-sig（Excel で文字化けしない）
- 列：ID、区分、碑名、変わった列、位置の変更
  - 碑名：追加・変更は新の碑名、削除は旧の碑名
  - 変わった列：変更のとき、違った列名を「、」でつなぐ（例「伝承内容、修正等公開日」）。追加・削除は空欄
- 並び順：区分（追加→変更→削除）、その中で ID の昇順
- 差分が0件でも、見出し行だけのファイルを保存する

## 画面へのまとめ表示（この順）
```
対象の県名: 徳島県
古いデータ: <パス>（取得日 2026-09-24、71基）　※初回は「古いデータ: なし（初回）」
新しいデータ: <パス>（取得日 YYYY-MM-DD、n基）
追加: n基 / 変更: n基（うち位置の変更 n基） / 削除: n基
（1件ずつ）[追加] 36xxx-xxx 碑名
           [変更] 36xxx-xxx 碑名（変わった列：…）
           [削除] 36xxx-xxx 碑名
差分ファイル: output/diff/....csv
```
- 0件のときは一覧の代わりに「前回からの変更はありません」と出す（成果物の作り直しは行う。データ取得日が新しくなるため）

## 成果物の作り直し（--dry-run でないとき）
次の順に、今の Python（sys.executable）で各スクリプトを実行する。作業フォルダはプロジェクトのルート。出力は画面にそのまま流す（取り込んで隠さない）。
1. src/load_monuments.py --pref P --raw <新データのパス>
2. src/add_elevation.py --pref P
3. src/add_river_coast.py --pref P
4. src/add_landform.py --pref P
5. src/make_comparison_points.py --pref P
6. src/add_elevation.py --pref P --target points
7. src/add_river_coast.py --pref P --target points
8. src/add_landform.py --pref P --target points
9. src/summarize.py --pref P
10. src/make_map.py --pref P
- 各ステップの前に「[3/10] 河川・海岸の付与（碑）」のように番号と内容を表示する
- 終了コードが0でなければ、そこで止めて「[n/10] ○○ で失敗しました。原因を直してからもう一度 update.py を実行してください（取得済みの分はキャッシュから読むので短時間で済みます）」と出し、更新履歴に「失敗（[n/10] ○○）」と記録して終了コード1で終わる
- Ctrl+C（KeyboardInterrupt）で止められたら、そこで止めて「中断しました」と出し、更新履歴に「中断（[n/10] ○○）」と記録して終了コード1で終わる（子のスクリプトが中断時に終了コード0で終わる場合があるため、update.py 側でも KeyboardInterrupt を受け止めること）
- ステップの実行は関数（例 run_steps(steps, runner)）に分け、テストで実行部分（runner）を偽物に差し替えられるようにする

## 更新履歴
- 保存先：output/update_history_<県コード>.csv（utf-8-sig）。ないときは見出し行を付けて作り、あるときは1行を追記する（見出しを重ねない）
- 列：実行日時（YYYY-MM-DD HH:MM）、県コード、旧データ取得日（初回は「なし」）、新データ取得日、旧データのファイル、新データのファイル、旧基数、新基数、追加、変更、うち位置の変更、削除、結果
  - ファイルはプロジェクトのルートからの相対パス、区切りは「/」（例 data/raw/2026-09-24/denshouhi_20260924.csv）。ルートの外なら絶対パス
  - 結果：「完了」／「失敗（[n/10] ○○）」／「中断（[n/10] ○○）」
- --dry-run のときは記録しない

## 自動テスト（tests/test_update.py。ネット接続なしで動くこと。本物の data/・output/ に触れないこと）
偽の CSV（REQUIRED_COLUMNS の12列、徳島36と他県の行を含む）を tmp_path に作って確かめる。
- a 追加・変更・削除がそれぞれ正しく判定され、件数と ID が期待どおり
- b 伝承内容だけ違う → 区分「変更」、変わった列「伝承内容」、位置の変更「なし」
- c 緯度だけ 0.0001 違う → 位置の変更「あり」、変わった列「緯度」。緯度の差が 0.00000001 のときは変更なし
- d 前後の空白だけの違い、空欄と NaN の違いは変更としない
- e 他県（例 12）の行の追加・変更・削除は数えない
- f 新データで ID が重複 → エラーで止まる（重複した ID が表示される）
- g 差分ファイル：保存先の名前、列、並び順（追加→変更→削除、ID 昇順）、utf-8-sig。0件でも見出し行だけ保存される
- h 初回（古いデータなし）→ 全件「追加」、ファイル名の旧取得日が none
- i --old 省略時の決め方：履歴の最後の「完了」行の新データ（「失敗」行は飛ばす）／履歴なし→2番目に新しい日付フォルダ／どちらもなし→初回
- j 更新履歴：初回は見出し付きで作り、2回目は追記（見出しが1行だけ）。--dry-run では記録されない
- k run_steps：偽の runner で、10ステップが決まった順と引数で呼ばれる。3番目で終了コード1を返すと4番目以降は呼ばれず、履歴の結果が「失敗（[3/10] …）」。runner が KeyboardInterrupt を出すと「中断（…）」
- l --old と --new が同じファイル → 終了コード1
