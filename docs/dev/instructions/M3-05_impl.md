# 指示書 M3-05（実装・仕様変更）　作成日：2026-10-01

最初に AGENTS.md を読んでから作業してください。

## 目的（このテーマ1つ）
河川側の標高の決め方を、「精しい値の最低値」から「**水際から20m以内の精しい値の最低値**」に変える。堤防の内側の低い町なかの値を拾わないようにするため。

## 背景（変更要求 CR-4。計画書 版5・2026-10-01 本人承認）
今は河川最近点から碑の方へ 0・5・10・20・30・50・100m の地点を調べ、精しい値の中で最も低い値を採用している。このため、川岸より奥の低い町なかの値を採用することがある（67基中11基）。
例：36383-001 牟岐川　0〜30m は水面（10mメッシュ 8.0〜7.0m）、50m が岸 3.1m、100m が町なか 2.4m → 今は 2.4m を採用。新しい決め方では 3.1m を採用する。

## 対象ファイル
- src/add_river_coast.py
- tests/test_add_river_coast.py

## やること（手順）
1. 定数を追加する（コメントで意味を書く）：`WATER_EDGE_WINDOW_M = 20`（水際＝最初に精しい値が出た地点から、何mまでの範囲で最低値を選ぶか）
2. `choose_bank_elevation(results, window_m=WATER_EDGE_WINDOW_M)` の決め方を次のように変える（上から順に当てはめる）。
   1. 状態が「通信エラー」の候補が1つでもある → 今までどおり「高さの差 取得不可（通信エラー）」
   2. 精しい値（今と同じ定義：数値で、種別が「10m」で始まらない）が1つ以上ある → **ずらし距離が最も小さい精しい値の地点**のずらし距離を d0 とし、精しい値のうちずらし距離が **d0 + window_m 以下**のものの中で最も低い値を採用。河川_状態「取得済」
   3. 精しい値がなく、P 自身の値が数値（10m メッシュ）→ 今までどおり参考値
   4. どれにも当たらない → 今までどおり「高さの差 取得不可（河川の標高なし）」
   - results の並び順に頼らず、ずらし距離（1番目の要素）で判断すること
3. process_river_coast から window_m を差し替えられるようにする（引数 `water_edge_window_m=WATER_EDGE_WINDOW_M`）。
4. 軽微な整理（M3_review-3 No.1）：使っていない `import warnings` を消す。
5. 自動テスト（ネットに接続しない）
   a. 既存の test_choose_bank_elevation の c〜f はそのまま合格すること（c は d0=5 で 5・10m が範囲内なので 2.9 のまま）
   b. 追加：0・5・10・20・30m が 10m メッシュ（8.0, 8.0, 8.0, 8.0, 7.0）、50m＝3.1（1m（レーザ））、100m＝2.4（1m（レーザ））→ **3.1** を採用・「取得済」
   c. 追加：5m＝3.0、20m＝2.5、30m＝2.0（すべて 1m（レーザ））、0m は "-----" → d0=5、範囲は25mまで → **2.5** を採用
   d. 追加：results の順番を逆にしても b と同じ結果になる
6. 報告書を書く前に `.venv\Scripts\python -m pytest` で全件合格を確かめ、`.venv\Scripts\python src\add_river_coast.py --pref 36` を実行して river_coast_36.csv を作り直す（キャッシュにある地点だけなので問い合わせは0回の見込み）。
