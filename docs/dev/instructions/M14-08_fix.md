## 目的（このテーマ1つ）
src/check_public.py の find_private_info で、PNG の iTXt チャンクの中身を正しく読み、圧縮された iTXt の中にあるパス・メールアドレスも見つけられるようにする。

## 不具合の内容
- 起きていること：iTXt を `chunk_data.split(b'\x00', 3)` で分けている。しかし iTXt の並びは
  `キーワード` `00` `圧縮フラグ（1バイト）` `圧縮方式（1バイト）` `言語タグ` `00` `翻訳キーワード` `00` `本文`
  で、圧縮フラグ・圧縮方式の1バイトも値が 00 になりうるため、区切りの数がずれる。圧縮した iTXt（フラグ 1）は本文の前に言語タグ等が残り、zlib の展開に失敗して `except: pass` で黙って飛ばされる
- 本来の動き：非圧縮でも圧縮でも、本文を取り出して3つのパターンを当てる
- Claude の確認（別環境）：PNG にメールアドレスを入れて find_private_info を実行 → 非圧縮 iTXt＝1件、zTXt＝1件、**圧縮した iTXt＝0件（見逃し）**
- 原因の見立て：src/check_public.py の `elif chunk_type == b'iTXt':` の分岐

## やること
1. src/check_public.py の iTXt の分岐だけを書き直す（ほかの分岐・パターン・表示の文は変えない）。手順：
   - 最初の `\x00` の位置までをキーワードとする
   - その次の1バイトを圧縮フラグ、その次の1バイトを圧縮方式とする（この2バイトは 00 かどうかに関係なく位置で読む）
   - その後ろから `\x00` を2回探して言語タグと翻訳キーワードを読み飛ばし、残りを本文とする
   - 圧縮フラグが 1 なら本文を zlib で展開する。展開に失敗したときは、その iTXt は飛ばしてよい（黙って飛ばす動きは今のままでよい）
   - 長さが足りず読めないときも飛ばす（IndexError などで止めない）
   - 本文を utf-8（読めない文字は置き換え）で文字にして text_chunks に加える（キーワードも今までどおり本文の前に付けてよい）
2. tests/test_check_public.py に足す（tmp_path に作る。既存の test_m14_07_png_private_info の make_png と同じ組み方でよいが、チャンクの種類（b'tEXt' 固定）を引数にするなど、iTXt を作れる形にする）：
   - (f) 非圧縮の iTXt（キーワード `Comment`、圧縮フラグ 0、方式 0、言語タグ・翻訳キーワードは空、本文にメールアドレス）→ 1件・種類「メールアドレス」・行番号 1
   - (g) 圧縮した iTXt（圧縮フラグ 1、方式 0、本文を zlib.compress したもの、中にメールアドレス）→ 1件・種類「メールアドレス」・行番号 1
   - (h) 言語タグ `ja`・翻訳キーワードがある圧縮 iTXt（中にユーザー名入りの Windows パス）→ 1件以上・種類に「Windowsパス（ユーザー名: <ユーザー名>）」を含む
   - (i) 本文に問題のない圧縮 iTXt、および途中で切れた壊れた iTXt（IndexError などで落ちないこと）→ 0件
   メールアドレスやユーザー名入りパスは、既存のテストと同じく文字列を分けて書くなどして、このリポジトリのファイルに実在の個人情報が入らないようにする（架空の値を使う。アドレスの「@」の前後、パスの「\」の前後は文字列を分けて書く）
