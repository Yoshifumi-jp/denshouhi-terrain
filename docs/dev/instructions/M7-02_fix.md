## 目的（このテーマ1つ）
src/analyze_denshou.py の計算（碑ごとの表・種別ごとの集計・碑群）を関数に分け、tests/test_analyze_denshou.py がその関数（＝本体の計算）を直接確かめるようにする。
**出力ファイルの中身（列・値・並び順）は変えない。** 実データで出力5ファイルの内容が修正前と同じであること。

## 対象ファイル
- 変更：src/analyze_denshou.py、tests/test_analyze_denshou.py
- 生成物：output/denshou_36.csv ほか5つ（作り直すが、中身は修正前と同じになること）

## 不具合の内容（ソース確認 M7_review-1 より）
- 起きていること：Claude がわざと main の中の計算を壊した7通り（下の表）を、テストがすべて見逃した（8 passed のまま）
- 本来の動き：計算の誤りはテストが失敗して知らせる
- 原因：区分・注記・集計・碑群の計算が main() の中にあり、テスト c・d・e・j はテストの中で同じ処理を書き直して確かめている。テスト f は出力ファイルの「有無」とバイト一致しか見ていない

## やること（手順）
1. 修正前の出力5ファイル（output/denshou_36.csv、denshou_summary_36.csv、disaster_groups_36.csv、fig/ の PNG 2つ）のハッシュ（Get-FileHash）を記録する（報告に貼る）
2. src/analyze_denshou.py の main() の中の計算を、次の関数に移す（名前はこのとおりにする）。main() はファイルの読み込み・関数の呼び出し・書き出し・グラフ・画面表示だけにする
   - `load_inputs(pref, root)` → 結合済みの DataFrame（monuments に elevation・river_coast を ID で結合したもの）
   - `build_denshou_table(df)` → output/denshou_*.csv と同じ列・同じ並び（ID 順）の DataFrame。区分・建立までの年数・年の数・発生年・注記・主な種別をすべてここで作る
   - `build_summary(denshou_df)` → output/denshou_summary_*.csv と同じ DataFrame
   - `build_groups(df)` → output/disaster_groups_*.csv と同じ DataFrame（並び順も含む）。グラフ用に碑群ごとの行が必要なら、同じ関数の戻り値に含めるか別の関数にする
   - 小数第1位への丸めは、上の関数の中で行うか、書き出しの直前に行うか、どちらかに統一する（丸める前の値をテストで確かめたい場合は、丸めない値を返す関数＋書き出し直前に丸める形がよい）
3. 「年の数」の行にある英語まじりのコメントを削除し、必要なら日本語で1行にする（M7_review-1 No.2）
4. tests/test_analyze_denshou.py を、本体の関数を呼んで確かめる形に直す。**テストの中で区分・注記・集計・碑群の計算を書き直さない**
   - c. 偽データ6基（指示書 M7-01 のテスト c と同じ答え）を DataFrame にして `build_denshou_table` に渡し、戻り値の 区分・建立までの年数・年の数・発生年・注記 を確かめる。**建立年は「1861」のように数字だけにする**（今の偽データは「1861年」で、全行に「注記あり」が付き注記の確かめにならない）。注記の答え：⑥は「複数の災害（最も古い年を使用）」だけ。別に「1664(慶長碑)、不明(宝永碑)」型の建立年の碑を1基加え、「建立年の記載に注記あり（最も古い年を使用）」が付くことを確かめる。発生年は⑥で 1854（最も古い年）
   - d. c の戻り値を `build_summary` に渡し、全種別の行が 碑の数・差あり・災害前の建立・対象外・不明・年数の中央値・最小・最大 で答えと一致すること（③のマイナスが年数に入らず、件数には1と数えられること）
   - e. 偽データで `build_groups` を呼び、碑の数・標高の中央値・最小・最大・除外数（「取得不可」1基）・海岸の値・碑のID・**並び順（碑の数の多い順→発生年の古い順→名前の順）** を確かめる。並び順の確かめには、碑の数が同じで発生年が違う碑群を含める
   - f. main を偽データで実行し、出力 CSV 3つを読み込んで、少なくとも1行ずつ値を答えと照合する（ファイルの有無とバイト一致に加えて）
   - j. 本物のデータの照合は `load_inputs("36", PROJECT_ROOT)` → `build_denshou_table` → `build_summary`・`build_groups` の戻り値で行う（答えは M7-01 のテスト j と同じ）。本物のデータの場所は PROJECT_ROOT 基準にする（実行時のフォルダに左右されない。M7_review-1 No.3）。ファイルへの書き出しはしない
   - g・h・i・a・b は今のままでよい
5. 自己チェックとして、下の「テストが気づくべき誤り」7通りを1つずつ本体に入れて pytest が失敗することを確かめ、確かめたら**本体を元に戻す**（戻した後に pytest が全件合格し、手順1のハッシュと出力が一致すること）。結果を報告に表で書く
   - ※ AGENTS.md の「元に戻す操作をしない」は、この確認のための一時的な書き換えには当たらない。エディタの Undo ではなく、書き換えた行を手で元の文字に戻すこと
6. `python src/analyze_denshou.py --pref 36` を実行し、出力5ファイルのハッシュが手順1と同じ（PNG が違う場合は理由を報告。CSV 3つは必ず同じ）であることを確かめる
