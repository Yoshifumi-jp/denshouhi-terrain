# 指示書 M2-01（実装）　作成日：2026-09-28

最初に AGENTS.md を読んでから作業してください。

## 目的（このテーマ1つ）
伝承碑ごとに、国土地理院の標高API（標高を返すサービス）で**標高(m)と傾斜(度)**を求め、碑の ID をキーにして保存する。
問い合わせ結果はキャッシュ（保存して再利用）し、途中で止めても続きから再開できるようにする。

## 対象ファイル
- src/add_elevation.py（新規）
- tests/test_add_elevation.py（新規）
- requirements.txt（requests を追加）
- src/load_monuments.py（下の「あわせて行う軽微な修正」のみ）

## 使う外部サービス
- 国土地理院 標高API：`https://cyberjapandata2.gsi.go.jp/general/dem/scripts/getelevation.php?lon=<経度>&lat=<緯度>&outtype=JSON`
- 戻り値の例：`{"elevation":1.6,"hsrc":"1m（レーザー）"}`
- データがない地点（海上など）では elevation と hsrc が `"-----"` になる
- 利用上の注意：サーバーに過度の負担をかけない（AGENTS.md のとおり、1件ごとに1秒以上空ける）

## やること（手順）
1. **入力**：`data/processed/monuments_<県コード>.csv`（M1 の出力）を読む。
   ファイルがない場合は「先に `python src/load_monuments.py --pref <県コード>` を実行してください」と日本語で表示して止める。
   コマンドの形：`python src/add_elevation.py --pref 36`（県コードは M1 と同じく 01〜47。今回は `all` は受け付けず、エラーにしてよい）
2. **標高の取得**：碑の緯度・経度で標高APIに問い合わせ、標高(m)とデータの種類（hsrc）を得る。
3. **傾斜の計算**：碑の地点から東西南北にそれぞれ **10m** 離れた4地点の標高も取得し、次の式で傾斜（度）を求める。
   - 東西の勾配 = (東の標高 − 西の標高) ÷ 20m、南北の勾配 = (北の標高 − 南の標高) ÷ 20m
   - 傾斜(度) = atan( √(東西の勾配² ＋ 南北の勾配²) ) を度に換算。小数1桁に丸める
   - 10m を緯度・経度の差に直す計算は、地球を半径 6,371,000m の球として扱う（経度方向は cos(緯度) で補正）
   - 4地点のうち1つでも標高が取れない場合、傾斜は「取得不可」とする（標高は取れていれば記録する）
4. **キャッシュ**：問い合わせ結果を `data/cache/elevation_cache.csv` に保存する（列：緯度, 経度, 標高, 標高データ種別, 取得日時。緯度・経度は小数6桁に丸めてキーにする）。
   - 1件取得するごとにすぐ追記する（途中で止めても、それまでの結果が残るように）
   - すでにキャッシュにある地点は問い合わせない
   - `"-----"`（データなし）もキャッシュする（何度問い合わせても同じ結果のため）
   - 通信エラー・タイムアウト（10秒）はキャッシュしない。3回まで間隔を空けて再試行し、それでも失敗したらその碑は「取得不可（通信エラー）」とし、次回の実行で再度問い合わせる
5. **間隔**：実際にサーバーへ問い合わせるときだけ、前回の問い合わせから1秒以上空ける（キャッシュから読むときは待たない）。
6. **出力**：`data/processed/elevation_<県コード>.csv`（UTF-8 BOM付き、ID 昇順）に次の列で保存する。
   ID, 碑名, 緯度, 経度, 標高_m, 標高データ種別, 傾斜_度, 取得状態, 取得日
   - 取得状態は「取得済」「取得不可（データなし）」「取得不可（通信エラー）」のいずれか。取れなかった数値の欄は空欄にする
   - 取得日は実行した日（YYYY-MM-DD）
7. **画面表示**：処理中は「12/71 36203-001 標高 3.2m 傾斜 1.4度」のように1行ずつ表示する。最後に次をまとめて表示する。
   対象の県名／基数／取得済の件数／取得不可の件数（内訳）／今回サーバーに問い合わせた回数／キャッシュから読んだ回数／保存先のファイル名
8. **中断と再開**：Ctrl+C（処理を途中で止める操作）で止めたときは、トレースバック（英語のエラーの長い表示）ではなく「中断しました。もう一度実行すると続きから再開します。」と表示して終わる。
9. **テストしやすい作り**：サーバーへの問い合わせ部分は関数に分け、テストでは偽物の関数に差し替えられるようにする（引数で渡す等）。待ち時間（1秒）もテストでは0にできるようにする。
10. **自動テスト**（tests/test_add_elevation.py。ネットに接続せず、tmp_path を使い、実データ・data/ フォルダを変更しないこと）：
   a. 傾斜の計算：4地点が同じ標高 → 0.0度
   b. 傾斜の計算：東が西より20m高く、南北は同じ → 45.0度
   c. 傾斜の計算：北が南より2m高く、東西は同じ（勾配10%） → 5.7度
   d. 10m を緯度の差に直した値が約 0.0000899度（小数7桁で一致）であること
   e. APIの戻り値の読み取り：数値のときは数値、`"-----"` のときは「データなし」と判定される
   f. キャッシュ：2基分を処理したあと同じ内容で再実行すると、問い合わせ回数が0回になる
   g. 再開：偽物の問い合わせ関数を途中（例：3回目）で例外を出すようにして止め、その後正常な関数で再実行すると、最終的な問い合わせ回数の合計が「基数×5」と一致し、結果が全件そろう
   h. 4地点のうち1つが「データなし」のとき、標高は記録され、傾斜は空欄・取得状態は「取得済」ではなくなる（どの表示にするかは実装に合わせてよいが、報告書に書く）
11. requirements.txt に `requests` を追加し、.venv にインストールする。
