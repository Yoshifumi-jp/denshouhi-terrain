# 指示書 M6-06（修正・公開前チェックの誤検出）　作成日：2026-10-03

最初に AGENTS.md を読んでから作業してください（特に「個人情報の扱い」）。
作業前に、エディタのタブをすべて閉じてから始めてください（ファイル消失の再発防止）。

## 目的（このテーマ1つ）
公開前チェックで、ユーザー名の部分を読みすぎて URL などを誤って検出する不具合を直し、テスト l を指示どおり（docs/dev を除外しない）にする。

## 対象ファイル
- src/check_public.py、tests/test_check_public.py

## 不具合の内容
- 起きていること：ホームのパス（unix_pattern）とユーザーフォルダのパス（win_pattern）で、ユーザー名の部分の文字の種類が広すぎる（区切りと < > … 以外は何でも読む）。そのため、URL の home の後ろの「index.html」から、空白・バッククォート・日本語の文を越えて、同じ行の後ろにある円記号までを「ユーザー名」とみなして検出する
- 本来の動き：ユーザー名の部分は、空白・タブ・バッククォート・引用符（' "）・括弧で終わる。URL の home の下のファイル名の後ろに区切りがなければ検出しない
- 原因の見立て（M6_review-4 No.2）：正規表現のユーザー名の文字の種類に、空白・バッククォート・引用符が除外されていない

## やること（手順）
1. 両方の正規表現で、ユーザー名の部分から空白類・バッククォート・引用符・括弧（半角・全角）・読点句点（、。）も除く。ほかの検出条件（伏せ字、%USERPROFILE%、noreply、二重に数えない）は変えない。
2. tests/test_check_public.py の test_check_real_project から、dev を含むパスを除く処理と、推測を書き連ねたコメントを消す。コメントは「l：本物のプロジェクトで0件、docs/data/summary_36.csv が対象に含まれる」程度の1〜2行にする。
3. テスト n2（新規）：1行の中に「URL（example.com の下の home フォルダの index.html）＋バッククォート＋日本語の文＋そのあとに円記号の重ねで書いた C ドライブのパス（ユーザー名は伏せ字 <ユーザー名>）」を並べた行 → 0件。同じ行で伏せ字の代わりに偽の名前にした行 → Windows の1件だけ。文字列はつなげて作り、テストファイル自体が検出されないようにする。
4. `.\.venv\Scripts\python.exe src\check_public.py` を実行する。本物のファイルで見つかったら、直さずに報告に書いて止まる。
