## 不具合の内容と直し方
1. **テストの不足（中）**：指示書 M6-01 のテストのうち次を追加・修正する（tmp_path の中だけで行う）
   - e：偽 CSV（徳島36と千葉12の行を含む）を tmp_path に作り、**main を通して**（--old・--new・--dry-run）実行し、差分ファイルに12の ID が1つも入らないこと、件数が36の分だけであることを確かめる
   - g：追加・変更・削除が混ざる例で、差分ファイルの並びが「追加→変更→削除、その中で ID 昇順」であること（例：追加 36001-009・36001-002、変更 36001-005・36001-001、削除 36001-008・36001-003 を入れ、ファイルの ID の並びを丸ごと照合）。ファイルの先頭3バイトが BOM（EF BB BF）であること
   - h：初回（--old なし・履歴なし・日付フォルダ1つ）で、碑が3基ある新データ → 全3件が「追加」、ファイル名の旧取得日が none
   - j：--dry-run で実行したあと output/update_history_36.csv が作られないこと
   - k：main を偽の runner で実行し（--dry-run なし）、10ステップが指示書 M6-01 の順と引数（スクリプト名・--pref・--target points・--raw <新データ>）で呼ばれることを、呼ばれたコマンドの一覧を丸ごと照合して確かめる
   - test_j の何もしない `with patch(...): pass` を消す
2. **作業フォルダ（中）**：子スクリプトは `PROJECT_ROOT / "src" / スクリプト名` の絶対パスで指定し、`cwd=PROJECT_ROOT` で実行する（default_runner で subprocess.run(cmd, cwd=PROJECT_ROOT)）。PROJECT_ROOT は `Path(__file__).resolve().parent.parent` にする。--raw に渡す新データのパスも絶対パスにする。テスト k の照合は、この形に合わせる
3. **使われない関数（中）**：run_steps（使われていない方）を削除する。実行は do_run_steps に一本化する（名前は run_steps に変えてよい。その場合はテストも合わせる）
4. **画面のパス表示（軽微）**：「古いデータ」「新しいデータ」のパスは to_rel_path で、プロジェクトのルートからの相対パスで表示する（ルートの外は絶対パスのままでよいが、報告に貼るときは AGENTS.md に従い伏せる）
5. **表示の順番（軽微）**：「[n/10] …」と「中断しました」「…で失敗しました」の print に flush=True を付ける
6. **黙って無視しない（軽微）**：determine_old_csv で、履歴の読み込みに失敗したとき、または最後の「完了」行の新データのファイルが見つからないとき、「注意：更新履歴の…が見つかりません。2番目に新しい日付フォルダと比べます」のような警告を表示する（処理は今のまま続ける）。警告が出ることをテストに1つ加える
