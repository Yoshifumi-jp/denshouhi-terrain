## 目的（このテーマ1つ）
実データを読むテストが、ハザード取得日を固定の日付で比べているため、県を作り直すたびに失敗する。取得日は実データのファイルから読んだ値と比べるように直す。

## 対象ファイル
- 変更する：tests/test_make_map.py、tests/test_build_site.py
- 新しく作る：docs/dev/reports/M14-02_report.md
- 変えないもの：上記以外のすべて（src/ は変えない）

## 不具合の内容
- 起きていること：`tests/test_make_map.py::test_real_hazard_popup` が失敗する（409行 `assert mon_df['ハザード取得日'].dropna().max() == '2026-10-04'`）。2026-10-14 に徳島を作り直し、data/processed/hazard_36.csv の「取得日」が 2026-10-14 になったため
- 本来の動き：実データの取得日が変わっても、テストの意味（取得日の最大値が正しく読み込まれ、ページに表示される）は保たれて合格する
- 原因の見立て（Claude のソース確認より）：tests/test_make_map.py 409行、tests/test_build_site.py の test_real_hazard_table の中の `"ハザード情報取得日：2026-10-14"`（M14-01 で 2026-10-04 から書き換えたもの）

## やること
1. 両方のテストで、期待する日付を data/processed/hazard_36.csv の「取得日」列の最大値（空を除く）から求める。読み方は `pd.read_csv(..., dtype=str, encoding='utf-8-sig')`。求めた値が `YYYY-MM-DD` の形であることも assert する
2. tests/test_make_map.py 409行：`== '2026-10-04'` を、上で求めた値との比較に変える
3. tests/test_build_site.py：`"ハザード情報取得日：2026-10-14"` を、上で求めた値を使った文字列との比較に変える
4. 偽のデータ（tmp_path に作るもの。test_make_map.py 340・357・423・439行など）の固定日付は、実データに関係しないので**変えない**

## やらないこと

- 上記2ファイル以外の変更
