## 目的（このテーマ1つ）

## 不具合の内容

## やること（手順）
1. テスト d で、index.html の「<h2>更新履歴</h2>」より後ろの部分だけを取り出し、その中で「<td>2026-09-24</td>」が「<td>2026-09-20</td>」より前にあることを確かめる。「2026-09-21」（失敗の行）がその部分にないことも確かめる。
2. 偽の更新履歴の日付は、偽の monuments のデータ取得日とも、偽の新データ取得日とも重ならない日付（例 実行日時 2026-08-10 と 2026-08-30）に変えると、なおよい（変えた場合はテストの期待値も合わせる）。
3. 試しに build_site.py の「新しい順」の処理（iloc[::-1]）を一時的に外すとテスト d が失敗することを確かめ、**必ず元に戻す**（元に戻したことを git diff src/ で確かめ、報告に書く）。
