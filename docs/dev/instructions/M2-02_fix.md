## 目的（このテーマ1つ）
「取得に失敗したときの記録」と「中断からの再開」を、指示書 M2-01 のとおり正しく動く・正しく確かめられる形に直す。

## 対象ファイル
- src/add_elevation.py
- tests/test_add_elevation.py

## やること（手順）
1. 傾斜の計算で周囲4地点のどれかが取れなかったとき、理由（「データなし」か「通信エラー」か）を呼び出し元に返すようにする。
2. 周囲の地点で「通信エラー」が起きた碑は、「取得不可（通信エラー）」と記録し、まとめ表示の通信エラーの件数・ID に数える。
   （標高が取れていれば標高は記録する。「データなし」の場合は今のままでよい）
3. tests/test_add_elevation.py の test_resume を、本当に中断・再開を確かめるテストに書き直す：
   - 1回目：偽物の問い合わせ関数が3回目の呼び出しで KeyboardInterrupt（Ctrl+C と同じ中断）を起こす。処理が「中断しました…」で終わること（SystemExit になること）を確かめる
   - 2回目：正常な偽物の関数で再実行する
   - 確かめること：2回目の問い合わせ回数が 8 回（2基×5地点＝10 から、1回目で取れた 2 回を引いた数）／キャッシュの行数が 10／結果が2基とも「取得済」
4. テストを1件追加する：周囲の1地点だけが3回とも通信エラーになる偽物の関数で実行すると、
   - その碑が「取得不可（通信エラー）」になる
   - 失敗した地点はキャッシュに保存されない
   - 正常な関数で再実行すると「取得済」になる
5. `python -m pytest` で全件合格すること。
