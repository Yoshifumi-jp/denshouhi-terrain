## 目的（このテーマ1つ）

## 不具合の内容（M4_review-3 No.3〜5）
- a：偽データでは組の差がすべて 0（A：10−10、B：20−20）。差の向き（碑−比較地点）を逆にしても、「碑の方が大きい割合」を「≧0」で数えても合格してしまう
- g：relocated_36.csv の一致を確かめていない
- h：足りないファイル名が出ることを確かめていない

## やること（手順）
1. テスト a 用に、差が「正・負」の両方になり、0 を含まない偽データを使う（既存の create_dummy_data の値を変えてよいが、b〜f の意味が保たれること。難しければ a 専用の偽データ関数を別に作る）
   - 例：碑 A=10（比較地点 5・7 → 中央値 6 → 差 +4）、碑 B=20（比較地点 22・30・40 → 中央値 30 → 差 −10）、碑 C は使える比較地点 0点
   - このとき 組の数 2、差の中央値 −3.0、碑の方が大きい割合 0.5、碑_中央値・比較地点_中央値も手計算の値を直接書く
   - 河川との高さの差_m など別の指標でも1つ、手計算の値を確かめる
2. テスト g：relocated の CSV も2回の内容が一致することを確かめる
3. テスト h：欠けたファイル名（例 monuments_98.csv、points_98.csv）が出力に含まれることを確かめる
