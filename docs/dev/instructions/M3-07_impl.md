## 目的（このテーマ1つ）
碑ごとに、国土地理院ベクトルタイル「地形分類（自然地形）」の地形分類名を付けて保存する。

## 使うデータ（計画書 M3・2026-09-29 Claude 調査）
- URL：`https://cyberjapandata.gsi.go.jp/xyz/experimental_landformclassification1/{z}/{x}/{y}.geojson`
- ズームレベルは 16 に固定する（z=16）。ダウンロード不要。取得したタイルはキャッシュして再利用する
- 中身は GeoJSON（ポリゴン）。土地条件図・脆弱地形調査・治水地形分類図などを合成したもので、全国一律ではない。山地などではタイルが無い（404）か、碑の位置にポリゴンが無いことがある → 「データなし」
- 利用条件：国土地理院コンテンツ利用規約。出典表記は「国土地理院ベクトルタイル提供実験（地形分類）」とする（README への記載は M5 で行うため、今回はコード先頭のコメントに書くだけ）
- 注意：応答が gzip 圧縮（先頭2バイトが 0x1f 0x8b）のまま返る場合がある。その場合は gzip モジュールで展開してから JSON として読む
- 属性（properties）は `code`（整数）だけ（1回目の作業で確認済み。例 5010301, 3050101, 3030101）。地形分類名は下の対応表で code から求める
- ズームレベル16は『詳細版』（主要な平野部のみ）。山間部の碑は「データなし」になる見込み（想定どおり。補完するかは結果を見て Claude と本人が判断する）

## やること（手順）
1. src/add_landform.py を新しく作る。入力は data/processed/monuments_{県コード}.csv、出力は data/processed/landform_{県コード}.csv（utf-8-sig）。起動方法は他と同じ `python src/add_landform.py --pref 36`。県コードの確認・エラー文は add_river_coast.py の main と同じ書き方にする
2. 緯度・経度から z=16 のタイル番号（x, y）を求める関数を作る（Web メルカトルの標準式）
3. タイル取得関数（ネット接続部分）は引数で差し替えられるようにする（テストで偽物を渡すため。add_elevation.py の fetch_func・sleep_fn と同じ考え方）
   - 成功：GeoJSON を返す
   - 404：「タイルなし」として扱う
   - それ以外のエラー（通信失敗、タイムアウト、500 など）：「取得不可」
4. キャッシュ：data/cache/landform/16/{x}/{y}.geojson に保存する（data/cache/ は .gitignore 済み）
   - 404 のタイルは、features が空の GeoJSON をキャッシュに保存する（再実行で問い合わせない）
   - 「取得不可」はキャッシュに保存しない（再実行で取り直す）
   - 同じタイルに複数の碑がある場合、問い合わせは1回だけ
   - 問い合わせの間は1秒以上空ける。2回目の実行は問い合わせ0回で終わること
5. 碑の点（経度・緯度）を含むポリゴンを探す。境界線上の点も含める（shapely の covers を使う）。複数あれば最初の1つを使い、件数を「地形分類_重なり数」に記録する
6. 出力列（この順）：ID、碑名、緯度、経度、地形分類名、地形分類コード、地形分類_重なり数、地形分類_状態、取得日
   - 地形分類_状態：「取得済」「データなし」（タイルなし、または点を含むポリゴンなし）「取得不可」
   - データなし・取得不可のときは、地形分類名・コードは空欄、重なり数は 0
7. まとめ表示：対象件数、状態ごとの件数、地形分類名ごとの件数（多い順）、問い合わせ回数、キャッシュから読んだ回数
8. 自動テスト（ネットに接続しない。偽物の取得関数を使う）
   a. タイル番号：緯度 34.066366・経度 134.584699・z=16 → (57268, 26164)
   b. 碑の点を含む正方形ポリゴン（名前「テスト低地」）がある → 地形分類名が「テスト低地」、状態「取得済」、重なり数 1
   c. タイルにポリゴンはあるが点を含まない → 「データなし」
   d. 404 → 「データなし」、キャッシュファイルができる、2回目の実行で取得関数が呼ばれない
   e. 通信エラー → 「取得不可」、キャッシュファイルができない
   f. 同じタイルの碑が2基 → 取得関数の呼び出しは1回
   g. 点がポリゴンの境界線上 → 「取得済」
   h. gzip 圧縮のバイト列が返る → 展開して正しく読める
   i. code 3030101 → 「氾濫平野・海岸平野」、code 5010301 → 「旧水部」、code 9999999 → 「不明（code=9999999）」で状態「取得済」
   j. 対応表の code に重複がない（1つの code が2つの名前に入っていない）
9. 報告書を書く前に pytest 全件合格を確かめ、本体を実行して landform_36.csv を作る（初回はネット接続あり。約70基・1秒間隔のため1〜2分の見込み）。続けてもう1回実行し、問い合わせ0回を確かめる
