## 目的（このテーマ1つ）
地形分類（人工地形）を碑・比較地点に付ける新しいプログラム `src/add_landform_artificial.py` を作り、`src/update.py` の段階に加える。試験県（徳島36・東京13・佐賀41）で実行し、下の「既知の答え」と一致させる。

## 対象ファイル
- 新規：`src/add_landform_artificial.py`
- 新規：`tests/test_add_landform_artificial.py`
- 変更：`src/update.py`（段階を2つ追加するだけ）
- 変更：`tests/test_update.py`（段階が2つ増えたことに合わせた期待値の修正だけ）
- 実行で作られるファイル：`data/processed/landform_artificial_{36,13,41}.csv`、`data/processed/landform_artificial_points_{36,13,41}.csv`、キャッシュ `data/cache/artificial/16/…`

## データ
- 配信：`https://cyberjapandata.gsi.go.jp/xyz/experimental_landformclassification2/16/{x}/{y}.geojson`（国土地理院ベクトルタイル提供実験「地形分類（人工地形）」。今の自然地形 …classification1 と同じ書き方）
- 404 は「タイルなし」。gzip で返ることがあるので `src/add_landform.py` の `default_fetch_func` と同じ扱いにする
- 分類名：`src/landform_codes.py` の `LANDFORM_CODES`（int のコード → 名前）を使う。人工地形の名前は「切土地・農耕平坦化地・干拓地・盛土地・埋立地・改変工事中」の6つ。コードが表にない、または表にあっても名前が人工地形の6つ以外のときは「不明（code=…）」とし、「表にないcodeの件数」に数える

## やること（手順）

### 1. `src/add_landform_artificial.py` を作る
`src/add_landform_region.py` の書き方（`_get_tile_data`・`_find_covering_features`・進捗表示・CSV の書き方）に合わせる。`lonlat_to_tile` は `src/add_landform.py` から import する。冒頭の docstring に出典（配信URL と https://github.com/gsi-cyberjapan/experimental_landformclassification ）を書く。

- コマンド：`python src/add_landform_artificial.py --pref 36`（碑）、`--target points`（比較地点）。`--pref all` や 01〜47 以外はエラー（既存と同じ文）
- 入力：
  - 碑：`data/processed/monuments_XX.csv`、比較地点：`data/processed/points_XX.csv`
  - 詳細版の結果：碑 `data/processed/landform_XX.csv`、比較地点 `data/processed/landform_points_XX.csv`（ID で突き合わせ、列「地形分類_状態」を見る）
  - 入力がないとき：碑・比較地点の CSV がなければ既存と同じ案内文。詳細版の CSV がなければ「先に python src/add_landform.py --pref XX（比較地点は --target points も）を実行してください」と出して終了コード1
- 出力：碑 `data/processed/landform_artificial_XX.csv`、比較地点 `data/processed/landform_artificial_points_XX.csv`（UTF-8 BOM 付き、改行 LF、入力と同じ行順）
  - 列：`ID, 碑名, 緯度, 経度, 人工地形名, 人工地形コード, 人工地形_重なり数, 人工地形_状態, 取得日`
- 1行ごとの判定（状態は4つ）：
  | 詳細版の「地形分類_状態」 | 問い合わせ | 人工地形_状態 | 名前・コード | 重なり数 | 取得日 |
  |---|---|---|---|---|---|
  | 取得済 | ZL16 のタイルを取得し、点を覆う（covers）地物を探す | 覆う地物あり →「取得済」 | 先頭の地物の code から | 覆う地物の数 | 実行日 |
  | 取得済 | 同上 | 覆う地物なし、またはタイルなし（404）→「人工地形なし」 | 空 | 0 | 実行日 |
  | 取得済 | 同上 | 通信エラー →「取得不可」 | 空 | 0 | 空 |
  | データなし | **しない** | 「範囲外」 | 空 | 0 | 実行日 |
  | 取得不可・空・詳細版に ID がない | **しない** | 「取得不可」 | 空 | 0 | 空 |
- キャッシュ：`data/cache/artificial/16/{x}/{y}.geojson`（LF）。404 は空の FeatureCollection として保存。通信エラーは保存しない。1回の実行の中で同じタイルは読み直さない（メモリ）
- 問い合わせの間隔：1回ごとに 1秒（`default_sleep_fn`）。キャッシュから読むときは待たない
- 進捗：`progress_line("地形分類（人工地形）", …)` で10件ごとと最後に表示（既存と同じ）
- 中断後の再実行：取得済みのタイルはキャッシュから読むので、続きから問い合わせる（既存と同じ仕組みでよい。途中までの CSV を書く必要はない）
- まとめ表示（この順・この文。状態の4行は0件でも出す）：
  ```
  対象件数: N
    取得済: n件
    人工地形なし: n件
    範囲外: n件
    取得不可: n件
  問い合わせ回数: n
  キャッシュから読んだ回数: n
  表にないcodeの件数: n
  人工地形名ごとの件数:
    盛土地・埋立地: n件
    …（件数の多い順、同数は名前順）
  ```
- 関数の形：`process_monuments(input_csv, landform_csv, output_csv, cache_dir, fetch_func, sleep_fn, clock=time.monotonic)`。`fetch_func(x, y)` は 404 で None を返し、その他のエラーは例外

「地形分類（地域版）の付与（比較地点）」の直後に次の2つを入れる。ほかの段階の中身・順番は変えない（段階の数は 18 → 20、`--no-site` のとき 17 → 19）。

### 3. 自動テスト `tests/test_add_landform_artificial.py`（12件以上）
ネットに出ない偽の fetch で作る。
- (a) 詳細版が取得済・覆う地物あり → 取得済・名前・コード・重なり数1・取得日あり
- (b) 詳細版が取得済・タイルはあるが覆う地物なし → 人工地形なし
- (c) 詳細版が取得済・404 → 人工地形なし、キャッシュに空の FeatureCollection が保存される
- (d) 詳細版がデータなし → 範囲外、fetch が呼ばれない
- (e) 詳細版が取得不可・詳細版に ID がない → 取得不可、fetch が呼ばれない、取得日が空
- (f) 通信エラー → 取得不可、キャッシュを作らない、取得日が空
- (g) 地物が2つ重なる → 重なり数2、先頭の地物の名前
- (h) 人工地形以外のコード（例 10701 氾濫平野）と表にないコード（例 99999）→「不明（code=…）」、表にないcodeの件数2
- (i) 同じタイルの2地点 → 問い合わせ1回
- (j) 2回目の実行はキャッシュだけで済む（問い合わせ0、キャッシュから読んだ回数＝タイル数）
- (k) 出力の列名・順番、BOM、改行 LF
- (l) まとめ表示の文（状態4行が0件でも出る）
- (m) 詳細版の CSV がないとき終了コード1と案内文（main の引数で確かめる）
- (n) 実データの照合（キャッシュだけを読む。キャッシュがなければ pytest.skip。偽の fetch はネットに出たら fail）：下の「個別の例」の9件
